## Why
Nothing pins the OpenSpec version or checks the artifacts: agents used whatever global `openspec` was installed, wrote changes by hand (none of the six archived changes has a `.openspec.yaml`), and `openspec validate --all --strict` 1.16.0 now reports five defective main specs. CI checks only `commit-kinds`.

## What Changes
- `openspec/cli.pin` pins the OpenSpec CLI (`1.16.0`); CI runs that version.
- The OpenSpec skills (propose, explore, continue, apply, update, ff, sync, archive, bulk-archive, verify) are generated by the pinned version for Claude Code (`.claude/skills/`) and Codex (`.agents/skills/`) and committed; `.claude/skills/` and `.agents/` become infrastructure paths.
- A new CI job validates OpenSpec: `openspec validate --all --strict`, no placeholder Purpose, a `.openspec.yaml` in every active change, skills' `generatedBy` equal to the pin, no open non-`[human]` task in the archive.
- `openspec/config.yaml` gains `rules.specs`, `rules.tasks` and `operations.apply` / `operations.archive` guidance that points at AGENTS.md.
- The defects the strict validation finds are fixed: the second `commit-kinds` requirement gets a scenario, `host-image-decode` and `text-font-size` get a real Purpose, the long requirements of `pointer-hit-test` and `text-input-pointer` are split without changing their meaning.

## Capabilities
### New Capabilities
- `openspec-workflow`: the fork's OpenSpec artifacts are made by one pinned version and validated by CI.

### Modified Capabilities
- `commit-kinds`: the self-test requirement gets a scenario.
- `pointer-hit-test`: the host-transform requirement is split into one behavior per requirement.
- `text-input-pointer`: the disabled-interactivity requirement is split into one behavior per requirement.

## Impact
- Infrastructure only: `openspec/`, `.claude/skills/`, `.agents/`, `.github/workflows/ci.yml`, `.github/infra-paths`, `AGENTS.md`. No library code changes.
